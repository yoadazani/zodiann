## Architecture Conventions

Every task follows these infrastructure conventions (established in ZOD-FND-001). Changing one requires an explicit decision recorded below.

**SDK and toolchain**
- **Run `test/architecture` with `dart test test/architecture` (as CI does), never `flutter test`.** Under `flutter test`, `Platform.resolvedExecutable` is the test runner, not `dart`, so the tests that spawn it (`launcher_icons_test`, `no_network_test`, `pure_dart_test`, `no_l10n_in_core_test`, `dependency_closure_test`) hang until the 30 s timeout; a whole-directory `flutter test` run lasted hours and was killed for memory (found in ZOD-UI-005). The whole directory takes about 20 s with `dart test`. Run the long workspace checks one process at a time.
- The Flutter SDK is pinned in `.fvmrc` (currently 3.50.0 / Dart 3.14.0) and used via FVM. Never use the global Flutter at `C:\Program Files\flutter` for project work.
- **Run Melos as `fvm dart run melos <command>`**, never a bare `melos`. The globally activated `melos` shim runs on whichever `dart` is first on PATH (the global 3.6.0) and fails with "Invalid kernel binary format version". `fvm dart run melos` runs the exact Melos version in `pubspec.lock` on the pinned SDK.
- Run other SDK commands as `fvm flutter …` / `fvm dart …`. Resolve dependencies with `fvm flutter pub get` or `fvm dart run melos bootstrap`. Plain `dart pub get` can't resolve the Flutter members.
- Melos (`sdkPath: .fvm/flutter_sdk`) puts the pinned SDK first on child processes' PATH, so commands inside Melos scripts use it automatically.
- FVM may not edit project files (`.fvmrc`: `updateVscodeSettings`, `updateGitIgnore`, `updateMelosSettings` all `false`).
- On Windows, FVM needs symlink permission: Developer Mode, or an admin terminal for `fvm use`.

**Workspace**
- One Dart pub workspace. All Melos config lives under `melos:` in the root `pubspec.yaml`. There is no `melos.yaml`.
- Every member declares `resolution: workspace`, `publish_to: none`, `environment.sdk: ^<pinned Dart minor>`. Flutter members also declare `environment.flutter: ">=<pinned Flutter>"`.
- New packages go under `packages/`, apps under `apps/`, C sources under `native/`. A new member must be added to the root `workspace:` list.
- Package kinds: pure Dart = `astro_core`, `gann_core`, `ephemeris_swiss`, `ephemeris_astronomy`. Flutter = `feature_wheel`, `feature_square`, `shared_ui`, `shared_storage`, `shared_export_xlsx`, `apps/astro_mobile`. `astro_core` and `gann_core` must stay pure Dart (ARCH-2). The root architecture tests enforce this on every test run, including indirect and conditional-import paths.

**Dependencies**
- There's a single root `pubspec.lock`, always committed. Members never get their own lock file.
- Use the latest stable release that's compatible with the pinned SDK. When a dependency can't be the latest, record why under Technical Decisions.
- Before adding a dependency, check it against Flutter's exact pins (currently `test_api 0.7.14`, `matcher 0.12.20`, `material_color_utilities 0.13.0`), because the shared resolution has to satisfy them.
- Hosted dependencies use a caret (`^x.y.z`). `pub add pkg:^x.y.z` run through `cmd //c` loses the `^` (cmd's escape character). Write `^^`, or edit the pubspec and run `pub get` (FND-014).

**Navigation** (established in ZOD-FND-014)
- **Routes:** `AppRoute` (`apps/astro_mobile/lib/src/navigation/`) holds the five spec routes in table order. The spec's `#name` is the `go_router` path `/name`, an identifier only.
- **Router:** one `GoRouter` from `buildAppRouter`, held in `appRouterProvider`. Never build a router in a widget's `build`: a rebuild would reset the screen. To start elsewhere, override the provider (DAT-007, tests).
- **Unknown routes:** any unmatched location redirects to `/wheel` (top-level redirect on `topRoute == null`).
- **Contract:** `AppRoute` is app-level and feature packages never import it. NAV-001's bar is route-independent, so the decision on where a feature-accessible route contract lives passes to the first feature-side navigation (ZOD-DAT-005). NAV-002's drawer is route-independent as well: the app maps `AppRoute.values` to the drawer's items, and `shared_ui` never imports `AppRoute`.
- **Deep links** (ZOD-NAV-003): the app registers the custom scheme `zodiann://` (Android: one BROWSABLE intent filter on `MainActivity`, no internet permission; iOS: `CFBundleURLTypes`; iOS unverified). `AppRoute.fromUri` (raw link) and `fromRoutedUri` (go_router's already-normalised URI) name the screen a link opens; the top-level redirect rewrites every scheme URI to a bare `/name`, or to `/wheel` when it names none, so no scheme is left in router state and a malformed link never shows an error. go_router ignores a URI's host, which is why the redirect is unconditional for scheme URIs.
- **Current screen:** `activeRouteProvider` and the shell both resolve it from the matched leaf (`AppRoute.fromPath`); `activeRouteProvider` is the source for anything outside the shell (the drawer mark, leave-screen consumers such as WHL-017's playback stop). Feature packages never import it: the app layer listens and calls a stop method on the feature. Its seed (read before the first frame from `routeInformationProvider`) must equal the screen the router settles on; `AppRoute.fromUri` applies go_router's own normalisation once to guarantee it.
- **A cold-start platform link overrides an injected `initialLocation`** (`defaultRouteName` wins), so a saved-screen restore (DAT-007) never beats a `zodiann://` link.
- **Warm links:** `WarmLinkEvents` (`navigation/warm_link.dart`) is a `WidgetsBindingObserver` that sees only platform pushes and returns `false`; `ZodiannApp` watches `warmLinkProvider` before `MaterialApp.router`, so it registers ahead of go_router's observer. The open drawer closes on every warm link and on nothing internal. Do not create the provider lazily.

**App shell** (established in ZOD-NAV-001)
- **Screens render inside `AppShell`** (one go_router `ShellRoute`), under the sticky `ZodiannTopBar`. The body extends behind the bar, so a scroll view inherits the bar's height as `MediaQuery` top padding. A scroll view with its own `padding` must add `MediaQuery.paddingOf(context).top` itself. Keep `AppShell` the only owner of the `Scaffold` app bar: a screen with its own `appBar` would stack a second bar.

- **Controls:** icon-only controls use `ZodiannIconButton` (46 × 46, plain / boxed); every control's states come from `ZodiannPressable` (UI-004).

**Fonts and network** (established in ZOD-FND-007)

**Typography** (established in ZOD-UI-002)

**Icons** (established in ZOD-FND-009)
- **Use:** `ZodiannIcon(ZodiannIcons.<name>)`; never a raw SVG, `Icon(Icons.…)` or an SVG package. Sizes come from `IconTheme`: the Zodiann themes give 20 (`ZodiannSize.icon`), and `ZodiannButton` gives 16 (`ZodiannSize.iconSmall`). Inside Material containers that inject 24 (`IconButton`, `AppBar`, `ListTile`), pass `size: ZodiannSize.icon` or set the container's `iconTheme` / `iconSize`.

**Drawer** (established in ZOD-NAV-002)
- **Open it with `showZodiannDrawer(context, builder: …)`** (a modal route on the root navigator, chosen by the product owner over `Scaffold.drawer`; the drawer is never docked inline, NAV-7). The builder returns a `ZodiannDrawer(wordmark:, groups:, closeLabel:, onClose:, versionLabel:, offlineLabel:)`; `AppShell` maps `AppRoute.values` into `ZodiannDrawerGroup`s. A second call from the same navigator while a drawer is open does nothing.
- **The version is app-owned and temporary:** `apps/astro_mobile/lib/src/app_version.dart` holds `1.0.0` until an authoritative version source exists; the drawer only displays what it is given.
- **Item taps** pop the drawer and then `go(route.path)`, unless the item is the active screen; a tap, or a warm-link close, is ignored once the drawer route is leaving (`ModalRoute.isActive`), so a second pop never removes the shell page (ZOD-NAV-003). The active mark follows `activeRouteProvider`, not the screen the drawer opened on.
- **Motion:** `easeOutCubic`, 240 ms opening and 180 ms closing (the close curve is flipped by hand, since Flutter applies a curve unflipped on reverse); instant under reduced motion. One progress drives the panel and the scrim. A swipe toward the start edge follows the finger 1:1 (mirrored in RTL); on release a fling of 365 px/s or more decides by direction, otherwise more than half open stays open; reaching the closed edge always closes. The gesture takes over from the position shown, so grabbing the panel mid-open does not move it.
- **Copy:** "Close menu" / "סגירת תפריט" is an approved exception to the `kit.js`-only copy rule. The active item uses `accent-strong` for icon and name (kit.css and the designer's PNGs); MASTER §5 says `text` and is not edited.
- **References:** the images in `packages/shared_ui/test/fixtures/drawer/` are generated visual references (headless Chrome from `_source/wheel.html?drawer=1`), not designer assets; `kit.css` stays authoritative. Regenerate only when a kit file changes: `fvm dart run tool/drawer/render_drawer_references.dart` (the manifest holds SHA-256 hashes of the kit files).
- **Pressable:** `ZodiannPressable` has optional `selected` and `semanticHint`; "not selected" is passed as `null`, because in Flutter 3.50 `false` is a state of its own that a screen reader announces.
- **Tests:** an unbounded `while` loop around a gesture hangs the runner when the code under test regresses; bound it and fail with a reason (`_dragUntil`).

**Tags** (established in ZOD-UI-009)
- **Use `ZodiannTag(variant:, label:)`**; the label is a localized string from the caller. The `+` / `×` mark is bound to the axis and diagonal variants (`ZodiannTagVariant.mark`), so a highlight is never colour alone (NFR-X4); never draw the mark yourself. Sizes are `ZodiannSize.tag / tagGap / tagOutline`; marks come from `ZodiannGlyphs.markAxis / markDiagonal` (plain text, not in `ZodiannGlyphs.all`).
- **Outline tags** (center, today) draw their 1.5 px outline inside the box with a `DecoratedBox`; never use a `Container` (it adds the border to the padding).
- **Layout:** a tag is at least 24 high and grows with the text scale; in a narrow parent the label ellipsizes. It fills the width of a stretch `Column` and the height of a horizontal `ListView`: wrap it in `Align` / `UnconstrainedBox` where that matters. Give it a non-empty label.
- **Neutral tags are weight 500** (kit.css; every other tag 600).

**Logo and launcher icons** (established in ZOD-FND-008)

**Buttons** (established in ZOD-UI-004)
- Buttons are `ZodiannButton` (`ZodiannButtonVariant`, `ZodiannButtonSize`); **at most one primary per screen region** (convention, reviewed in PRs).

**Data model and JSON** (established in ZOD-FND-012)
- Model classes are immutable `final class`es with hand-written `toJson` / `static fromJson(Object?)`, value equality and `toString`. No codegen, no `equatable` / `collection`.
- Constructors validate invariants and throw `ArgumentError`. `fromJson` throws **only** `FormatException` for any invalid input, using `gann_core`'s internal strict readers (`json_read.dart`) and `buildOrFormatError`. Missing keys are errors; a nullable field must still be present (explicit `null`).
- JSON shape: camelCase keys equal to field names. Enums as their `name`. Sealed variants carry a `"type"` discriminator. Doubles accept any JSON number.
- Date-times: UTC timestamps are canonical ISO-8601 ending in `Z`. Moments with an offset use `OffsetDateTime` (canonical ISO-8601 `±HH:MM`). Parsing is strict (`iso8601.dart`): impossible fields are rejected, never normalized.
- Lists held by models are unmodifiable copies.
- `HighlightRule.colorToken` is a MASTER.md §2.2 **role-family key** (`axis`, `diag`, `eighth`, …). The UI resolves it to `<family>-fill` / `<family>-ink`, plus the bare `<family>` accent where the design defines one.
- Derived results (e.g. `Crossing`) have no JSON and are never persisted. `test/architecture/crossing_not_persisted_test.dart` scans the persistence packages, currently `packages/shared_storage/lib`. **Add any new persistence package to its `storageLayers` list.**

**Angles and the node** (established in ZOD-EPH-001)
- Normalize every longitude with `normalizeDegrees` (`astro_core`), never a bare `x % 360`. Dart's `%` can return exactly `360.0` for tiny negatives, and `EclipticPosition` rejects that.
- The mean-node formula exists once (`meanAscendingNodeAt` in `mean_node.dart`). `EphemerisPort` adapters `with MeanAscendingNodeFormula implements EphemerisPort` and answer `Body.node` **before** checking `coveredRange`, because the node is formula-based and not bounded by the data range.
- The node's retrograde state is the fixed flag `Body.hasConstantMeanRetrograde` ("℞ Mean"), never derived from speed.

**Square of Nine spiral** (established in ZOD-GAN-001)
- Use `spiralCell(n)` / `spiralNumberAt(x, y)` from `gann_core`. Never re-derive positions in UI or export code.
- Coordinates are relative to cell 1, with **x right and y down** (screen). The orientation is SQ-8's fixed one: 2 left of 1, clockwise. 90° (north) is the column of cells straight above cell 1, and 270° straight below.
- The valid range is `1 … maxSpiralNumber` / rings `0 … maxSpiralRing`, shared by both directions. The center (`n = 1`) has `null` index, steps and angle.
- Highlight classification works on the integers `i` and `k`, not on the `double` angle `θ`.

**Square of Nine highlights** (established in ZOD-GAN-002)
- `classifyHighlight(spiralCell(position))` is the single source of a cell's highlight category (axis / diagonal / eighth / none). Classify by spiral **position**, never by the displayed number or date. That's the working assumption while the numeric-anchor decision (TASKS.md §6.2) is open.
- Colors come from the square's rules via `highlightRuleFor(category, config.highlights)` → `colorToken`. A missing rule means no highlight. Never hard-code colors per category.
- Arbitrary user-defined rule evaluation is ZOD-EXT-008. Don't evaluate `HighlightRule.match` ad hoc in UI or export code.

**Square of Nine dates** (established in ZOD-GAN-003)
- **Time-zone rule (NFR-A3):** date-and-time cells are `anchor.instant + stepHours·(n−1)` absolute hours, shown in the device's current zone via `localWallClock(…, const DeviceTimeZone())`; the DST hour jump is visible, never corrected. Dates mode is `anchor.wallClock` date + (n−1) days, unaffected by DST or travel. Today's cell uses the device zone.
- Use `cellDate` / `cellMoment` / `todayCellInDatesMode` / `nowCellInDateTimeMode` / `daysAfterAnchor` / `hoursAfterAnchor`; never re-derive dates in UI or export code. Inject `LocalTimeZone` so code stays testable.
- Display through `formatCellDate` (`d.m.yy`) and `formatCellTime` (`HH:MM`); English month-first order is ZOD-L10-010, wrapping these.
- Calendar dates and wall clocks are UTC-flagged `DateTime` carriers; all inputs must be UTC (else `ArgumentError`). Out-of-range cells throw `ArgumentError`, never wrap.

**Accuracy tests** (established in ZOD-TST-002)
- Accuracy and verification suites live in `packages/<pkg>/test/accuracy/`. Their expected values come from an **independent** reference: only the code under test is imported (`show …`), with literal reference coefficients and test-local helpers. Production constants and helpers are never used for expectations.
- Format and display oracles **parse the output back** and compare against the inputs, rather than rebuilding the expected string the way production does (T-FMT-1). Wall-clock carriers are checked at both ends of the day, to catch a stray `toLocal()` (effective on a non-UTC machine).
- `gann_core` suites live in `packages/gann_core/test/accuracy/` too. DST cases use **test-local fake zones mirroring real rules** (Israel / New York 2026 in T-GAN-4) and never the machine zone; calendar oracles work on records, not `DateTime` date arithmetic. Large-square properties are checked over all 3,721 cells, not samples.
- Each verification suite is accompanied by a **mutation proof**: alter each production constant or behaviour it guards, observe the failure, restore, and record it in the commit message.
- The shared reference date set is `packages/astro_core/test/fixtures/reference_dates.json`. It's add-only: increment `version` when adding; never drop or change an instant. A v1-subset test enforces this.
