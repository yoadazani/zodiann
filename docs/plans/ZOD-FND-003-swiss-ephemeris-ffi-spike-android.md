# ZOD-FND-003 Swiss Ephemeris FFI spike, split: Android now, iOS pending: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (default, sequential). Nothing here is independent enough for subagents: every task consumes the previous task's output (vendored source, then binding, then device run, then findings).

**Goal:** Prove on Android that the Swiss Ephemeris C library can be vendored unchanged, built through the Flutter toolchain, bound with Dart FFI, packaged with data files and run on a device to return a correct longitude, and write down what the iOS half must still prove. **ZOD-FND-003 is not complete and is not marked complete until a real iOS computation is verified.**

**Architecture:** Swiss Ephemeris sources are vendored byte-for-byte under `native/swisseph/upstream/`. `packages/ephemeris_swiss` gets a build hook (`hook/build.dart`, native assets) that compiles them into `libswisseph` for Android only, ffigen bindings, and a thin hand-written wrapper. The data files live once, as Flutter package assets of `ephemeris_swiss`; at run time they are copied to a real directory and Swiss Ephemeris is pointed at it. An `integration_test` in `apps/astro_mobile` runs the computation on the Android emulator.

**Tech Stack:** Dart 3.14 / Flutter 3.50.0 (pinned by `.fvmrc`), `hooks ^2.2.0`, `code_assets ^2.0.0`, `native_toolchain_c ^0.19.4`, `logging ^1.3.0`, `ffi ^2.1.4`, `ffigen ^20.1.1` (versions are those of the pinned SDK's own `package_ffi` template), Android NDK 28.2.13676358 (the installed one, and Flutter 3.50's default `ndkVersion`), `integration_test`.

**Spec:** `assets/zodiann-specification.md`: ARCH-6 (line 554), R-7 (line 734), "Running Swiss Ephemeris in Flutter" and "Data files" (lines 391, 393). Task file: `docs/development/foundations-architecture/ZOD-FND-003-spike-swiss-ephemeris-ffi-binding-on-android-and-ios.md`. Dependency: ZOD-FND-001 (done). Licensing: `docs/decisions/ZOD-FND-010-swiss-ephemeris-license.md`, `docs/licensing/source-availability-policy.md`.

## Review Focus

1. **"Unchanged" is broken by line endings on checkout.** Local trees use `core.autocrlf=true` and the `windows-latest` runner's Git for Windows defaults to the same, so LF files are checked out as CRLF and a hash of the bytes on disk would fail on `Full suite` (the Windows job runs the root `test/` through `melos run test`, `useRootAsPackage: true`; `Core` on Linux runs only `test/architecture`) even when `git add` changes nothing. Expected: D1's scoped `-text` attributes are added unconditionally before the first `git add`; the committed blobs are compared with upstream's tree (`gh api repos/aloistr/swisseph/git/trees/<sha>?recursive=1`); the byte-hash test is proved in a fresh `git clone -c core.autocrlf=true` and on the first CI run. Test: Task 1's `swisseph_vendored_test.dart` recomputes each file's blob SHA from the bytes on disk.
2. **A correct Sun longitude proves nothing about the data files.** The built-in Moshier fallback returns a longitude within about an arcsecond of the right value with no file at all. Expected: every device assertion also requires `SEFLG_SWIEPH` in the returned flags and an empty `serr`, and a **negative control** (an empty directory) must return the Moshier flag with a non-empty `serr` (Task 4).
3. **A date outside the packaged file silently falls back.** `sepl_18` covers 1800 to 2400. Expected: a test at 1799-12-31 shows what the library returns (Moshier flag and a warning, not an error) so EPH-002 knows it must check the flags to honour R-2; the `_18` pair is a spike subset and FND-011 owns the real range (Task 4).
4. **The emulator uses 16 KB pages.** A 64-bit shared library whose `LOAD` segments are not 16 KB aligned fails to `dlopen` there. Expected: `llvm-readelf -lW` shows `LOAD` alignment `0x4000` on arm64-v8a and x86_64 (the 16 KB requirement applies to 64-bit ABIs; NDK r28 aligns them by default); the armeabi-v7a value is recorded as information and does not fail the check; recorded for REL-002 and REL-003 (Task 4).
5. **Only x86_64 is executed.** The shipped phone ABI is arm64-v8a. Expected: all three ABIs (arm64-v8a, armeabi-v7a, x86_64) are built and alignment-checked; the findings say plainly that only x86_64 ran, unless the owner authorizes the Galaxy S22 Ultra over adb (then the same test runs on arm64 and the result is recorded) (Task 4, Task 6).
6. **The hook must not compile C on the host.** Any `dart test` or `flutter test` whose graph includes `ephemeris_swiss` (including `astro_mobile`'s 208 widget tests) would run the hook; the local host has no MSVC and `windows-latest` would pay a C build in its 240 s budget. Expected: the hook emits no asset unless the target OS is Android (D3); local `melos run test` stays green; a measured CI run shows `Full suite` under budget (Task 3, Task 7).
